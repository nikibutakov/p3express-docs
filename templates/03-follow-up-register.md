# Шаблон 3. Реестр последующих действий

> Шаги A06 (первичное заполнение рисками) и D01 (ежедневное ведение).
> Владелец: менеджер проекта. **Один журнал для трёх типов записей**:
> риски, проблемы, запросы на изменения.

## Как заполнять

- **Риск** — возможное будущее событие. **Проблема** — уже случившееся.
  **Запрос на изменение** — предложение изменить содержание проекта.
- Новое фиксируйте **немедленно**, не полагаясь на память. Доступ к реестру
  должен быть максимально простым (в т.ч. с телефона); если недоступен —
  запишите в блокнот и перенесите как можно скорее.
- Риск описывайте как **само событие**, а не его последствия. Без общих и
  расплывчатых формулировок.
- **Не перегружайте записи оценками** (вероятность/ущерб) — минимум данных,
  максимум действия.
- У каждой записи — **ответственный** из команды; распределяйте на многих,
  не концентрируйте на менеджере.
- Меры — **проактивные, реалистичные, с измеримым результатом**. «Усилить
  контроль» — не мера. «Провести нагрузочный тест до пятницы» — мера.
- Не занимайтесь только «тушением пожаров»: нерегулируемые риски — главный
  источник будущих проблем.
- Критичные записи, которые не решаются командой, — эскалируйте спонсору (D01).

## Шаблон

```markdown
# Реестр последующих действий — «<название проекта>»

| № | Дата | Тип | Описание | Ответственный | Действия | Статус | Закрыта |
|---|------|-----|----------|---------------|----------|--------|---------|
| 1 | | риск | | | | открыт | |
| 2 | | проблема | | | | в работе | |
| 3 | | изменение | | | | закрыт | |

**Тип:** риск / проблема / изменение ·
**Статус:** открыт → в работе → закрыт (+ дата закрытия)
```

### Примеры записей

| № | Дата | Тип | Описание | Ответственный | Действия | Статус |
|---|------|-----|----------|---------------|----------|--------|
| 1 | 2026-01-10 | риск | Демо выпадает на воскресенье, врачей-«выходного» дня в сид-данных нет | Я | Добавить в демо-сид врача, работающего вс, до 2026-01-15 | закрыт |
| 2 | 2026-01-12 | проблема | Заказчик не подтвердил список специальностей | Б | Отправить перечень на согласование, напомнить 2026-01-14 | в работе |
| 3 | 2026-01-15 | изменение | Добавить на внешний сайт карту проезда | Ф | Оценить объём, внести в карту результатов | открыт |
