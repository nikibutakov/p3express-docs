# Шаблон 4. Реестр «Здоровье проекта»

> Шаг B02 «Провести ежемесячное ревью». Владелец: менеджер проекта.
> Сюда попадают **оценки внешнего ревьюера** — другого руководителя проекта
> или эксперта организации — по итогам каждого месячного цикла.

## Как заполнять

- Раз в месяц (B02) попросите другого РП/эксперта разобрать ваши
  ежемесячные управленческие действия и внести оценки в этот реестр.
- Зачем внешний взгляд: погружённый в проект менеджер часто не замечает
  проблем; попутно это обмен опытом между руководителями проектов.
- Если оценка низкая — вернитесь и **повторите часть действий** цикла, прежде чем
  продолжать.
- Помогите ревьюеру быть честным: критика действий — не критика менеджера;
  выстроите доверительное взаимодействие.
- Оценивайте **качество управления**, а не сам продукт: выполнены ли шаги
  B/C/D/E цикла, живы ли документы, ведётся ли реестр.

---

## Шаблон

```markdown
# Реестр «Здоровье проекта» — «<название проекта>»

| Цикл | Дата | Ревьюер | Планирование (B01–B05) | Еженедельно (C01–C04) | Ежедневно (D01–D02) | Закрытие цикла (E01–E03) | Комментарии ревьюера |
|------|------|---------|------------------------|-----------------------|---------------------|--------------------------|----------------------|
| 1 | | | 🙂 / 😐 / 🙁 | 🙂 / 😐 / 🙁 | 🙂 / 😐 / 🙁 | 🙂 / 😐 / 🙁 | |
| 2 | | | | | | | |

**Шкала:** 🙂 хорошо · 😐 есть замечания (указать) · 🙁 требует переделки
```

### О чём спрашивать ревьюера (подсказка)

- План цикла основан на Карте результатов? Приоритеты ясны команде?
- Прогресс фиксировался еженедельно? Отклонения отрабатывались, а не копились?
- Реестр последующих действий живой: новые записи появляются сразу?
- Уроки цикла извлечены и превращены в конкретные улучшения?
- Документы (Резюме, Карта) актуальны или отстают от жизни?
