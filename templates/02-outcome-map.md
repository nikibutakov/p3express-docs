# Шаблон 2. Карта результатов

> Шаг A05 «Определить ожидаемые результаты». Владелец: менеджер проекта.
> Основа для планирования (B01) и измерения прогресса (C01). Заполняет пробел
> между абстрактным Резюме проекта и повседневными задачами.

## Как заполнять

- Результаты формулируйте **существительными, а не глаголами**:
  «работающая система записи», а не «разработать запись». Фокус на конечных
  продуктах, не на действиях.
- Стройте **иерархию** (дерево, 2–4 уровня). Формат свободный: список,
  таблица или mind map — главное, чтобы команде было удобно.
- К каждому результату при необходимости — **краткое описание**
  (содержание, качество, критерии приёмки).
- **Зависимости** между результатами отмечайте, если их много; если мало —
  планируйте по приоритетам, а не по расписанию (гибрид допустим).
- Карта может уточнить Резюме проекта — синхронизируйте изменения.
- Архив похожего проекта — лучший источник для реалистичной карты.

---

## Шаблон

```markdown
# Карта результатов — «<название проекта>»

- Дата: <YYYY-MM-DD> · Версия: <1.0>

## Дерево результатов

- **1. <крупный результат>** — <краткое описание: содержание / качество>
  - 1.1. <результат> — <описание/критерий приёмки>
  - 1.2. <результат>
- **2. <крупный результат>**
  - 2.1. <результат>
  - 2.2. <результат> *(зависит от 1.1)*
- **3. <крупный результат>**

## Статусы (обновляются еженедельно, C01)

| Результат | Статус | Комментарий |
|-----------|--------|-------------|
| 1.1 | не начат / в работе / готов / принят | |

## История изменений

| Дата | Что изменилось |
|------|----------------|
|      |                |
```
