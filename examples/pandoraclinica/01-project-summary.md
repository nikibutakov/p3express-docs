# Резюме проекта — «PandoraClinica»

- Дата: 2026-11-05 · Версия: 1.1 · Статус: в работе (этап экранов)
- Менеджер проекта: Никита (роль «Я» — интеграция, девопс, основа фронта)
- Спонсор: руководитель практики (заказчик демонстрации)

## 1. Цель и ожидаемые выгоды

Работающая система поликлиники «Пандора»: поток пациентов через регистратуру,
график врачей со слотами записи, живая очередь с талонами и табло, направления
между врачами и вечерняя выгрузка приёмов раздельно по гражданству РФ/не-РФ.

**Выгоды:**
- сквозной демо-сценарий «админ → регистратор → пациент → врач → табло →
  выгрузка» проходит без ручных операций и перезапуска сервисов;
- воспроизводимое окружение (демо-сид одной командой, CI из трёх проверок);
- командная практика: три роли (Б — бэкенд, Ф — экраны, Я — интеграция)
  в едином процессе веток и ревью.

## 2. Ожидаемые стоимость и срок

- Срок: этапы по плану команды (PLAN.md); база и каркас фронта закрыты
  за первую неделю (2026-11-02), экраны — следующий крупный блок.
- Ресурсы: 3 участника команды; инфраструктура — GitHub Actions (free),
  PostgreSQL 17, портативные инструменты разработки.

## 3. Требования и ожидания по качеству

- CI: три обязательных job (линт ruff/mypy/pylint; pytest с PostgreSQL 17;
  фронтенд eslint + tsc + build) — зелёные на main, мерж только через PR;
- экраны работают по реальным эндпоинтам с типами из OpenAPI (без «временных»
  fetch без типов);
- сообщения об ошибках и интерфейс — на русском; состояния загрузки/пусто/ошибка
  на всех экранах;
- демо-данные (`python -m app.seed --demo`) наполняют пустую базу целиком.

## 4. Границы проекта

**Входит:** бэкенд FastAPI (16 таблиц, роли admin/registrar/doctor), монорепо
фронта (staff/public/shared), демо-сид, CI, деплой через docker compose +
nginx (раздел D плана).

**Не входит:** реальная интеграция с «облаком» (выгрузка — в имитацию каталога/
S3-совместимое хранилище), прод-эксплуатация за пределами демо-стенда,
мобильные приложения, интеграция с ФИС/Госуслугами.
