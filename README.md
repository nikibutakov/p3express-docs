# P3express Docs — документация проектов по методологии P3.express

Практический набор для ведения проектной документации по **P3.express (П3экспресс)** —
минималистичной методологии управления проектами. Всё на русском, всё в Markdown:
шаблоны можно положить в репозиторий любого проекта и вести вместе с кодом.

## Что здесь

```
templates/     4 шаблона документов P3.express с инструкциями по заполнению
examples/      Заполненный пример комплекта для реального проекта PandoraClinica
methodology/   Метод в двух словах: этапы, циклы, роли, чек-листы
SOURCES.md     Источники и атрибуция (контент методологии — CC BY 4.0)
```

## Четыре документа P3.express

| № | Документ | Зачем | Когда ведётся |
|---|----------|-------|---------------|
| 1 | [Резюме проекта](templates/01-project-summary.md) | Цель, выгоды, срок/стоимость, качество, границы, стейкхолдеры | Создаётся на запуске (A04), пересматривается весь проект |
| 2 | [Карта результатов](templates/02-outcome-map.md) | Дерево результатов проекта — основа плана и измерения прогресса | Создаётся на запуске (A05), детализируется при планировании цикла (B01) |
| 3 | [Реестр последующих действий](templates/03-follow-up-register.md) | Единый журнал рисков, проблем и запросов на изменения | Каждый день (D01): новое — сразу в реестр |
| 4 | [Реестр «Здоровье проекта»](templates/04-project-health.md) | Оценки внешнего ревьюера качества управления | Раз в месяц (B02) |

Методология нарочно минималистична: **33 шага, 7 этапов, 4 документа, никаких
других обязательных артефактов**. Подробности — в [methodology/overview.md](methodology/overview.md).

## Как начать вести документацию по P3.express

1. Скопируйте `templates/` в свой проект (например, в `docs/p3express/`).
2. Запустите проект по этапу A — [чек-лист запуска](methodology/checklists.md):
   назначьте спонсора, менеджера, ключевую команду.
3. Заполните Резюме проекта и Карту результатов (шаги A04–A05), внесите первые
   риски в Реестр последующих действий (A06).
4. Работайте циклами по 2–4 недели: планирование → недели → закрытие цикла —
   и каждый месяц добавляйте запись в Реестр «Здоровье проекта».
5. Документы — «живые»: правьте по ходу, храните в одном месте с историей
   изменений (git подходит идеально).
